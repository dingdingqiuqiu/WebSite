### 分层职责与调用规则

| 层         | 职责                                  | 规则                                            |
| ---------- | ------------------------------------- | ----------------------------------------------- |
| controller | 参数绑定、调用 service、包装 `Result` | 不含业务逻辑                                    |
| service    | 业务逻辑、事务边界(`@Transactional`)  | 可调用其它 service、utils                       |
| mapper     | 单表/联表数据访问                     | 仅 `BaseMapper` + 链式 Lambda,无 DAO 层         |
| entity     | 表映射                                | 非表字段用 `@TableField(exist = false)`         |
| dto        | 接口出入参                            | 与 entity 分离,防止表结构泄露分层职责与调用规则 |

## POM文件

pom.xml 就一件事：**把项目从口头约定变成可执行声明**。它只回答三个问题。

**一、我是谁**
`groupId + artifactId + version` 唯一标识项目。这是身份。

https://central.sonatype.com/可以查到

**二、我需要什么**
`dependencies` 声明能力需求，`scope` 控制每个依赖在哪个阶段生效。

这里的关键是版本从哪来。Spring Boot 的 `parent` 本质是一份**版本清单**：它内部的 `dependencyManagement` 把几百个库的兼容版本定死，但**只定版本，不引入依赖**。规则很简单——依赖在清单里就不写版本，不在清单里就必须自己写。`dependencyManagement` 和 `dependencies` 的分工也在于此：前者管版本，后者管引入。

`scope` 的本质是**按阶段划分需求**。编译时只需要接口（JDBC），运行时才需要实现（MySQL 驱动），所以驱动是 `runtime`；Lombok 只在编译期生成代码，运行时不需要，所以打包时要排除。一个依赖在哪个阶段需要，就用哪个 scope。

`starter` 则是**能力的打包**：引一个 starter，等于引入一整套互相兼容的库。

**三、我怎么构建**
`build` 管“怎么造”，`dependencies` 管“用什么”。`spring-boot-maven-plugin` 把项目打成可执行胖 jar——代码、依赖、内嵌 Tomcat 全在里面，`java -jar` 就能跑。

**最后，pom.xml 存在的意义就一句话**：让任何机器读同一份文件，得到同一个构建结果。它消灭的不是“麻烦”，是“不确定性”。

## 启动类

### 1.启动类概述

```java
@SpringBootApplication
public class TfShengHouZhiApplication {
    public static void main(String[] args) {
        SpringApplication.run(TfShengHouZhiApplication.class, args);
    }
}
```

我们这里主要将`@SpringBootApplication`，其相当于以下三个注解

```java
@SpringBootConfiguration // 我是配置类，run 从我开始读配置
@EnableAutoConfiguration // 读所有 starter 的自动配置清单，按条件加载
@ComponentScan(          // 从当前包开始扫我自己的 Bean
    excludeFilters = {
        // 支持 @SpringBootApplication(exclude = Xxx.class) 关掉某个自动配置
        @Filter(type = FilterType.CUSTOM, classes = {TypeExcludeFilter.class}),
        // 排除自动配置类，避免和 @EnableAutoConfiguration 重复注册
        @Filter(type = FilterType.CUSTOM, classes = {AutoConfigurationExcludeFilter.class})
    }
)
```

### 2.启动配置类注解

`@SpringBootConfiguration` 的最终身份：一个 Bean + 一个配置类 + 一个配置源。

```java
@SpringBootConfiguration
    │
    │ 元注解
    ▼
@Configuration
    │
    │ 元注解
    ▼
@Component
    │
    │ 语义
    ▼
启动类是一个 Bean
    │
    ├─ 因为 @Configuration，它里面可以有 @Bean 方法
    │       └─ @Bean 方法返回值也是 Bean
    │
    └─ 因为 @SpringBootConfiguration，它是 Spring Boot 的配置源
            └─ run 和 @SpringBootTest 能找到它
```
### 3.引入的starter类自动配置注解

```bash
你引入 spring-boot-starter-web(来自于POM文件)
    │
    ├─ 带来一堆 jar（Spring MVC、Jackson、Tomcat……）
    │
    └─ 带来一个文件：
        META-INF/spring/...AutoConfiguration.imports(自动配置清单)
            │
            ▼
@EnableAutoConfiguration 启动
    │
    ├─ 扫描 classpath 上所有 jar
    │
    ├─ 读取所有 .imports 文件
    │
    ├─ 汇总成一份自动配置类清单
    │
    └─ 逐个判断条件：
        ├─ @ConditionalOnClass    → classpath 有没有
        ├─ @ConditionalOnMissingBean → 用户有没有自定义
        └─ @ConditionalOnProperty → yaml 有没有配
            │
            ▼
        条件满足的自动配置类生效
            │
            ▼
        创建对应的 Bean（DataSource、RedisTemplate……）可以直接操作SQL或Redis等
```

### 4.自动扫包配置类

扫描当前包及子包下，所有带 `@Component` 的类，注册为 Bean。

```
@ComponentScan 启动
    │
    ├─ 扫描 com.tfsh 及子包
    │
    ├─ 找到所有带 @Component 的类
    │
    └─ 应用 excludeFilters：
        │
        ├─ TypeExcludeFilter
        │       └─ 用户写了 @SpringBootApplication(exclude=...) 的，排除
        │
        └─ AutoConfigurationExcludeFilter
                └─ 自动配置类，排除（交给 @EnableAutoConfiguration 处理）
        │
        ▼
    剩下的才是用户自己的 Bean
```

附注：

```java
@ComponentScan                    @EnableAutoConfiguration
─────────────                    ──────────────────────
扫用户自己的 Bean                  加载自动配置类产生Bean
（@Service、@Controller、           （DataSourceAutoConfiguration、
 @Repository、@Configuration）      RedisAutoConfiguration……）

        │                                    │
        │                                    │
        └──────────┬─────────────────────────┘
                   │
                   ▼
            两者都产生 Bean
                   │
                   ▼
            必须划清边界
                   │
                   ▼
            excludeFilters 就是边界
```

## 配置yaml文件

前面讲到自动配置类会根据yaml文件自动生成bean，在yaml文件的视角链路如下：
```yaml
server:
  port: 8081

spring:
  application:
    name: tfshz

  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: ${DB_URL:jdbc:mysql://127.0.0.1:3306/tfshz?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true}
    username: ${DB_USERNAME:root}
    password: ${DB_PASSWORD:}

  data:
    redis:
      host: ${REDIS_HOST:127.0.0.1}
      port: ${REDIS_PORT:6379}
      password: ${REDIS_PASSWORD:}
      lettuce:
        pool:
          enabled: true
          max-active: 10
          max-idle: 10
          min-idle: 1
          time-between-eviction-runs: 10s

  jackson:
    default-property-inclusion: non_null

mybatis-plus:
  type-aliases-package: com.tfsh.entity

logging:
  level:
    com.tfsh: debug
  pattern:
    dateformat: mm:ss.SSS
```

在idea中给运行配置加上密码的环境变量即可
